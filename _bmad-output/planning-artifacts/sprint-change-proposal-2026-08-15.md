# Sprint Change Proposal — Evidence-Grounded Physical and Syscall Anomaly Research

## 1. Issue Summary

The academic progress seminar exposed a cross-cutting validity problem rather
than an isolated defect in one story. The prototype executes, but several
current design choices cannot support the intended dissertation conclusion:

- simulator ranges, noise, dynamics, consensus divergence scales, SCADA
  tolerances, fault offsets, autoencoder adequacy gates, hyperparameters, and
  anomaly thresholds include project-selected numbers without adequate source
  or experimental provenance;
- the physical pipeline mixes engineering values, current, percentages, noise,
  and rates on incompatible scales, causing RPM-scale values to dominate the
  autoencoder reconstruction loss;
- the current OPC UA service is circular because it projects consensus into the
  SCADA source before comparison;
- the current ADFA-LD and LID-DS paths are labelled offline classifiers and do
  not represent syscalls generated by the project edges;
- the current LID-DS adapter does not implement the official 2021 layout;
- HAI has not been implemented;
- the planned comparison lacks synchronized physical and syscall observations
  from the same custom runs and therefore cannot support a fusion claim;
- LSTM and GRU have been treated as selected solutions without a fair,
  same-protocol comparison against simpler baselines.

The trigger is classified as both a **new stakeholder requirement** and a
**correction of previously misunderstood scientific boundaries**. It is not a
request to erase the prototype. Existing results remain useful as historical
and exploratory evidence but require explicit limitations.

## 2. Evidence Supporting the Change

### 2.1 Repository evidence

The repository audit identified anonymous or conflicting executable values in
the simulator, sensor behavior, consensus, SCADA comparison, fault injection,
runtime configuration, autoencoder lifecycle, thresholds, and offline model
runners. It also confirmed that:

- physical autoencoder tensors currently combine physical PV, loop current,
  percent range, physical-unit noise/rate, heuristic stability, and diagnostics;
- runtime training uses a small and conflicting configuration, including a
  sequence length of two and a single training epoch in the active lifecycle;
- reconstruction-error thresholds are calculated from runtime/baseline data
  rather than loaded as a frozen calibration artifact;
- live Go consensus receives engineering values because the Python client drops
  current and diagnostics from the transaction;
- the OPC UA service receives consensus values before comparison;
- the runtime uses a fixed compressor command rather than the requested
  automatic experimental schedule;
- the existing LID adapter expects a layout and semantics different from the
  official LID-DS 2021 loader;
- no HAI adapter or runtime edge syscall producer exists.

The attached autoencoder report documents a current model trained on 30
artifacts and 29 overlapping windows, with 27 mixed-scale features, one epoch,
batch size one, and latent size four. It shows that the pipeline can emit an
anomalous score for some replay injections, but not that replay is detected
reliably across operating regimes.

### 2.2 Official and primary-source evidence

- Rockwell documents scaling between electrical signal units and engineering
  units, including 4 mA, 12 mA, and 20 mA examples corresponding to 0%, 50%,
  and 100%. [Rockwell PointMax Analog I/O Manual](https://literature.rockwellautomation.com/idc/groups/literature/documents/um/5034-um003_-en-p.pdf)
- NI documents the generic two-endpoint 4–20 mA scaling method. [NI scaling guidance](https://knowledge.ni.com/KnowledgeArticleDetails?id=kA00Z000000PASfSAO)
- A real shaft-speed transmitter supports programmable 4 mA and 20 mA RPM
  endpoints, so RPM does not need to change to 1–5 V. [Electro-Sensors FB420](https://www.electro-sensors.com/products/shaft-speed-sensors/fb420)
- The official LID-DS recording framework uses Docker and Sysdig, providing a
  direct precedent for controlled workloads that emit real kernel syscalls.
  [LID-DS Recording Framework](https://github.com/LID-DS/LID-DS/wiki/LID-DS-Recording-Framework%3A-Documentation-and-Installation)
- HAI is a versioned physical/SCADA dataset collected from boiler, turbine,
  water-treatment, and HIL processes. Its repository recommends eTaPR for
  temporal anomaly evaluation. [Official HAI repository](https://github.com/icsdataset/hai)
- Original LSTM and GRU publications justify them as temporal model candidates,
  while large empirical comparisons do not establish a universal winner.
  [LSTM](https://doi.org/10.1162/neco.1997.9.8.1735)
  [GRU](https://aclanthology.org/D14-1179/)
  [Empirical RNN comparison](https://proceedings.mlr.press/v37/jozefowicz15.html)
- NIST AI RMF calls for documented test sets, metrics, uncertainty, benchmark
  comparisons, and repeatable TEVV. [NIST AI RMF Measure](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)

## 3. Core Decisions

### 3.1 Two detection modalities only

The project has two detection modalities:

1. **Physical instrumentation**, represented in the custom prototype by raw
   electrical current, deterministic span normalization, quality, and derived
   engineering values.
2. **Linux host syscalls**, represented as categorical kernel events generated
   by controlled edge workloads.

The 4–20 mA signal is a representation of the physical modality, not a third
modality. An autoencoder is a model, not a dataset or modality.

### 3.2 Dataset roles

- **ADFA-LD:** external syscall benchmark; ordered numeric syscall sequences;
  no fabricated timestamps and no executable replay of its numeric IDs.
- **LID-DS 2021:** external syscall benchmark and capture-method reference;
  official roles and recording schema must be preserved.
- **HAI 23.05:** external physical/SCADA benchmark using its native versioned
  representation; it is not converted wholesale to mA and does not validate
  the compressor.
- **PTFP-Custom-v1:** the new synchronized project dataset containing custom
  physical observations and actual captured edge syscalls from the same runs;
  it is the only source eligible for physical-plus-syscall fusion claims.

### 3.3 Parameter governance

Every executable v2 numeric parameter must have a stable parameter ID and one
of the following classifications:

- `direct`: stated directly by an authoritative source for the selected profile;
- `derived`: obtained through a recorded formula over sourced inputs;
- `measured`: obtained through a preserved pilot or calibration;
- `preregistered_factor`: deliberately selected before test execution;
- `mock`: required by the simulator and explicitly limited to that mock profile.

Every parameter entry records value, unit, source ID, exact locator,
derivation, applicable profile, and approved experiment. A citation to an
unrelated process does not make a number transferable.

The requested 25%–75% command is a `preregistered_factor` named
`speed_reference_pct` or `capacity_reference_pct`. It is not described as
electrical power or as a universal compressor operating range.

The unimplemented July Epics 9–16 are superseded by the revised Epics 9–18 in
Section 6. They are planning history, not implementation dependencies.

### 4.2 PRD conflicts

The PRD and May overlay currently conflict with the approved direction by
requiring an LSTM-only path, a generic stratified 80/20 split, supervised HIDS
reintegration, and fixed or configurable numbers without provenance. The July
overlay improves physical/HIDS separation but still targets HAI 20.07, lacks a
synchronized custom syscall branch and fusion, and freezes unsupported
experimental constants.

The next PRD overlay must:

- define the two modalities and four evidence sources;
- establish raw current as the primary custom edge evidence while retaining
  derived engineering values;
- define PTFP-Custom-v1 and restrict fusion to synchronized custom runs;
- establish parameter provenance and truth isolation as requirements;
- replace LSTM-only wording with candidate-model comparison;
- replace HAI 20.07 with pinned HAI 23.05;
- supersede physical promotion of ADFA/LID models;
- remove universal numeric performance gates without an explicit evidence
  classification.

### 4.3 Architecture conflicts

The current architecture places SCADA after consensus and lacks canonical
signal, syscall, truth, detector-output, fusion, and evaluation contracts. It
also permits runtime threshold recomputation and promotion records that do not
bind weights, preprocessing, schema, calibration, and runtime identity.

The architecture overlay must introduce:

- `SignalObservation.v2` with raw electrical, normalized, derived engineering,
  quality, timestamp, and instrument-profile fields;
- a pre-consensus plant snapshot branch to an independent OPC UA writer/server
  and a distinct `asyncua.Client` reader;
- controlled Linux edge workloads and `SyscallEventBatch.v1` on a separate
  high-volume path outside physical consensus;
- isolated `ScenarioTruth.v1` storage unavailable to detectors;
- immutable deployment bundles and detector score contracts;
- late fusion after detector-specific calibration;
- versioned MinIO namespaces and legacy-to-shadow-to-active flags;
- dashboard as a read model only.

### 4.4 UX impact

No standalone UX specification exists. The implemented dashboard requires an
additive final-stage correction only. It must:

- show raw mA, normalized span, and engineering value as representations of the
  same physical modality;
- show physical, syscall, and fusion detector channels separately;
- distinguish benchmark, custom, fixture, reference, and measured evidence;
- display model/schema/threshold/provenance identities and limitations;
- remain unable to import, split, train, calibrate, promote, fuse, or rewrite
  scientific results.

### 4.5 Secondary technical impact

- Docker images and dependency states require immutable identities for formal
  campaigns.
- MinIO requires persistent storage, append-only artifact keys, verification,
  and restoration testing.
- Python and Go consensus contracts must change atomically.
- External LID parsing and syscall capture require a pinned Linux boundary.
- HAI adapters must be release-specific.
- Existing autoencoder artifacts cannot be loaded against v2 features.
- Existing reports require append-only errata rather than silent rewriting.

## 5. Options Evaluated and Recommended Approach

### Option 1 — Direct adjustment

**Viable:** Yes.  
**Relative effort:** High.  
**Risk:** High during cross-contract migration, controlled by shadow execution.  
**Benefit:** Preserves useful implementation and evidence.

### Option 2 — General rollback

**Viable:** No as the primary approach.  
**Relative effort:** Medium but scientifically unproductive.  
**Risk:** High loss of traceability without resolving methodological gaps.  
**Use:** Only targeted quarantine of invalid claims and superseded plans.

### Option 3 — MVP/claim review

**Viable:** Yes and required.  
**Relative effort:** Medium for planning; implementation remains high.  
**Risk:** Low if scope language is corrected before code.  
**Benefit:** Aligns the dissertation claim with evidence actually obtainable.

### Recommended path — Hybrid

Use **Direct Adjustment + MVP/claim review**:

1. preserve all v1 code and artifacts as legacy evidence;
2. supersede unimplemented incompatible planning;
3. implement v2 additively in shadow;
4. activate each boundary only after its evidence gate;
5. produce the final dissertation claim as a paired ablation on synchronized
   custom runs, with external benchmarks reported separately.

No calendar estimate is asserted before the capture and storage pilots. The
sequence and evidence gates, rather than invented durations, control progress.

## 7. Scientific Evaluation Protocol

### 7.1 Split and leakage rules

- Split complete trace, scenario, file, session, or run groups before windows.
- Fit preprocessing only on training evidence.
- Select threshold only on declared calibration/validation evidence.
- Freeze model, preprocessing, threshold, and evaluation policy before locked
  test access.
- Keep scenario truth, attack labels, and future intervals structurally absent
  from detector inputs.
- Preserve all planned executions, including failures and unfavorable results.

ADFA-LD uses official roles and trace identities, with any additional normal
calibration/test grouping preregistered before windows. LID-DS preserves its
official training/validation/test structure. HAI uses official normal training
files, a declared normal temporal calibration partition, and official test
files. PTFP-Custom splits complete independent runs.

### 7.2 Metrics

Report all applicable outcomes, not only selected successes:

- PR-AUC, precision, recall, F1, FPR, and confusion matrix;
- event/range recall, false events per operating hour, and time to detection;
- threshold sensitivity and calibration behavior;
- parameter count, training/inference time, memory, and bundle size;
- modality availability, missingness, syscall gaps/drops/duplicates, and
  capture overhead;
- dispersion or confidence intervals across independent runs.

No metric value is a universal gate unless it is documented as direct,
derived, measured, or preregistered for the relevant experiment. Missing a
target does not authorize removing the run.

### 7.3 Final matrix boundary

External datasets are reported in separate physical and syscall benchmark
tables. There is no global champion across incompatible domains. The central
dissertation comparison is a paired ablation on PTFP-Custom-v1:

- physical detector only;
- syscall detector only;
- preregistered late-fusion decisions on the same held-out runs/windows.
