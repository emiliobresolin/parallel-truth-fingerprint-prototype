# Physical Candidate Comparison v1

Story 13.3 defines pure, immutable comparison contracts for physical detector candidates. A frozen plan requires LSTM-AE, GRU-AE, and one transparent baseline; no field can name a preselected superior family.

Every candidate/repetition run binds the same schema, partition, frozen preprocessing state, normal-training evidence, validation evidence, tuning access, resource budget, and candidate configuration. The validator retains all planned runs, including failed, stopped, blocked, and budget-exceeded outcomes. It refuses missing/replaced runs, unresolved identities, altered shared inputs, and incomplete non-selected outcomes.

Model-specific exceptions are allowed only when they were preregistered in the frozen candidate definition and the exact exception closure is recorded on each run.

The contracts contain opaque identities only. They deliberately have no test, calibration, truth, labels, fitted weights, window values, or publication side effects. `finalize_physical_candidate_comparison` only canonicalizes a supplied record and diagnostics; it does not fit, select, publish, or authorize any scientific activity.
